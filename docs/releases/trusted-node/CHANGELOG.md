# Trusted-node (bisq2-api docker) release notes

One `## <version>` section per image release, newest first. The text under the heading is the English note; `### <locale>` subsections carry the StartOS translations. See README.md for the rules and how the release workflow reads this file.

## 2.1.14.1

**No action needed.** Bisq Connect stays paired.

This maintenance update keeps the node on Bisq 2 API 2.1.14 and brings fixes for Bisq Connect.

- **Banned account data:** The node can now check a seller's payment account data against the banned list, so the next Bisq Connect release can warn you not to pay a seller whose account data is banned and cancel the trade for your protection.
- **Offerbook:** Offers from banned or ignored makers, and sell offers whose maker lacks the reputation for the amount, are no longer listed, and the offer counts match the list.
- **Restarts:** If the node fails to start, it now exits so it is restarted automatically instead of running without the API. A pairing code left over from an earlier run is deleted at startup.
- **Trades:** Cancelling or rejecting a trade no longer waits for the trade chat message to be delivered.

It also includes storage pruning and performance fixes.

## 2.1.14.0

Security update. Moves the node to Bisq 2 API 2.1.14, a security release: new storage signatures and owner-bound storage keys, stricter checks when offers are taken, separate Tor circuits per identity, pairing secrets stored only as hashes, and authentication on every WebSocket connection. The node's Tor daemon is raised to 0.4.9.14. Update before 25 November 2026: from then on updated nodes no longer accept data signed only the old way, so a node still on 2.1.13 can miss offers and messages and its trades can stall. Bisq Connect stays paired, but asks you to accept the updated terms again. Fixed-price offers published through a 2.1.13 node must be created again. Logs written by earlier versions contain the node's private keys: this version hides them in its own log files, but do not share older copies such as container logs, log viewer exports or backups. Downgrading to 2.1.13 is not supported; going back would require pairing every device again. Update the node first, then Bisq Connect. Bisq 2 release: https://github.com/bisq-network/bisq2/releases/tag/v2.1.14

## 2.1.13.0

Security update. Upgrades the node's Tor daemon to 0.4.9.13, the Tor Project's emergency security release of 23 September 2026 that fixes a series of high-severity issues affecting clients, onion services and relays (it also includes the 0.4.9.12 fixes). Moves the node to Bisq 2 API 2.1.13, which Bisq 2 marks as required to continue trading. Update your node as soon as possible, then update the Bisq Connect app. Tor advisory: https://forum.torproject.org/t/security-release-0-4-9-13/22178 — Bisq 2 release: https://github.com/bisq-network/bisq2/releases/tag/v2.1.13
